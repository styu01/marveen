# Béla Home v1 — Functional Inventory (M0.2)

Classification of every v1 feature as **Working**, **Partial**, or **Fake** (looks implemented, isn't real/reliable). Source: full code read of `kitchen/server.js` and `kitchen/public/index.html`, cross-referenced with `kitchen/DEV-SPEC.md` (2026-07-23 technical audit).

## Working (no v2 blocker beyond porting to the new stack)

| Feature | Note |
|---|---|
| Push-to-talk voice (manual start/stop) | Whisper STT + gpt-4o chat + OpenAI TTS, works end to end |
| Timers | Preset buttons, alarm-until-acknowledged, survives page refresh via localStorage |
| Reminders (one-shot) | Server-side CRUD, 60s polling |
| Weather widget | wttr.in, city configurable in Settings (client-side only) |
| Person profiles (data layer) | 4 hardcoded profiles, CRUD API exists, injected into system prompt |
| Chat history | localStorage, restored across sessions |
| Markdown/link rendering | Hand-rolled but functional, XSS-safe |
| Shopping list (single device) | Add/toggle/remove, emoji auto-categorization |
| Shopping list email | Resend integration, works once a key is configured |
| BÉLA-voiced error messages | Timeout / offline / generic branches |

## Partial (works in the common case, breaks under real conditions)

| Feature | Why it's partial |
|---|---|
| Wake word ("Szia Béla") | Auto-starts recording, but stop is still manual — no VAD, exactly the gap v2 fixes in M4 |
| Calendar requests | Confirms the *parsed* date immediately, but actual Google Calendar write depends on the main BÉLA agent's informal heartbeat (no cron, up to ~30 min, sometimes never) |
| Morning briefing | Real when it exists, but nothing guarantees it gets generated — depends on the same informal heartbeat |
| Recipe search | Real TheMealDB data when the ~35-word HU→EN dictionary happens to match; silently falls back to unverified model output otherwise |
| Shopping list sync | Works per-browser; a second device (Erika's phone) sees a different, empty list — this is the #1 reason v2 moves it server-side |
| "PWA" | Add-to-homescreen meta tags only — no manifest.json, no Service Worker, not actually installable/offline-capable |

## Fake / misleading (v2 must not repeat this pattern)

| Feature | Reality |
|---|---|
| "Server-side timers survive tablet sleep" | Never claimed working, but worth flagging explicitly: timers are 100% client-side JS intervals; a genuinely sleeping tablet does not fire them. v1 never promised otherwise, but v2's persistent-timer requirement (BH spec §17.2, ARCH STATE-001) exists specifically to fix this |
| Settings persistence | `/api/settings` accepts `emailTo`/`city` but silently drops them server-side; only `resendKey` is actually persisted. The frontend masks this by always sending values explicitly from localStorage, so it "looks" like it works — but it's per-browser, not per-installation |
| Chat weather always says Budapest | Independent of whatever city is configured in Settings; only the widget respects the setting. A user who changes city gets inconsistent answers between the widget and the voice assistant |
| Background music via YouTube embed | "Plays AC/DC" is real, but it's a live YouTube stream via a hidden IFrame of one specific public video ID, not a licensed local asset — fragile if that video is ever taken down/blocked |

## Explicitly out of scope for this inventory

- No live load/performance data exists for v1 — it was never used long enough to generate any.
- No voice-accuracy baseline test (M0.3) has been run — the v1 server is currently stopped and there is no tablet actively testing it. **This needs Istvan's involvement** (recording real test sentences on the real device) and is deferred until the v2 Voice Stage A (M4) exists to test against; testing the frozen v1 pipeline further has no value now.

## M0.4 — Backlog lock

Per the v2 dev spec (§0.2, §2.3, R-10): no feature beyond what's written in the two spec documents (`docs/bela-home-v2/v2-user-spec-extracted.md`, `docs/bela-home-v2/v2-dev-spec-extracted.md`) may be added to the v2 roadmap without Istvan's explicit sign-off. This inventory does not add anything — it only classifies what already exists in v1 for migration-decision purposes.
